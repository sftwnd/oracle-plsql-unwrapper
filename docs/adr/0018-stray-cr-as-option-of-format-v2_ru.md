# 0018. Случайный CR как параметр формата V2

[English version](0018-stray-cr-as-option-of-format-v2.md)

## Контекст

Что делать со случайным CR текста V2 (ADR 0007) — единственная настройка, которую `UnwrapOptions` хранил собственным
полем, с методом `with`, геттером и системным свойством пакета API. Читает её только формат V2: в тексте единицы V1
случайного CR не бывает, а реализация V1 берёт свои параметры (`layout`, `in`) через `FormatUnwrapper.withOptions` и
эту настройку игнорирует. Настройка появилась раньше механизма параметров отдельного формата (ADR 0017), по которому
формат сам описывает свои параметры, а командная строка задаёт их по имени.

Выпуск 1.0.0 опубликован с этим API: `UnwrapOptions.withKeepStrayCr`, `keepStrayCr()`, `KEEP_STRAY_CR_PROPERTY`,
конструктор `V2FormatUnwrapper(boolean)` и флаг командной строки `--keep-stray-cr`.

## Решение

- Настройка — параметр `strayCr` формата V2 со значениями `space` (по умолчанию) и `keep`:
  `UnwrapOptions.withFormatOption("V2", "strayCr", "keep")`, `--format-option V2.strayCr=keep`.
  `V2FormatUnwrapper.options()` описывает его, поэтому справка командной строки показывает его под форматом, а
  `withOptions` берёт его и отклоняет другое значение с `IllegalStateException`, как V1 свои параметры.
- Чего параметр не задаёт, формат читает из своего системного свойства `com.github.sftwnd.oracle.unwrap.v2.strayCr`,
  для каждой единицы, как свойства V1; параметр важнее.
- `UnwrapOptions` хранит только параметры форматов, по имени. `defaults()` ничего не задаёт и свойств не читает.
- API выпуска 1.0.0 продолжает работать и объявлен устаревшим до удаления в следующем мажорном выпуске:
  `withKeepStrayCr(true)` — это `withFormatOption("V2", "strayCr", "keep")`, а `withKeepStrayCr(false)` задаёт
  `space`; `keepStrayCr()` говорит, равен ли параметр `keep`; свойство `com.github.sftwnd.oracle.unwrap.keepStrayCr`
  (`true` в любом регистре сохраняет CR) V2 читает после своего; `V2FormatUnwrapper(boolean)` задаёт параметр;
  `--keep-stray-cr` добавляет параметр `V2.strayCr=keep` на своём месте среди аргументов и в справке не показывается.

## Обоснование

- Настройка, которую читает один формат, принадлежит этому формату: справка описывает её только там, где формат есть на
  class path, а SPI ничего не знает о том, что форматы делают с текстом.
- Один механизм для всех форматов оставляет один способ задать параметр в API, командной строке и системных свойствах:
  `V1.layout`, `V1.in` и `V2.strayCr` различаются только именем.
- Значения `space` и `keep` называют, что происходит с CR, как `source` и `canonical` называют раскладку; boolean
  назвал бы только одно из двух.
- Устаревший API отображается на параметр без второго пути в коде: формат читает параметр как единственный источник, а
  старое свойство — только после своего, поэтому процесс, задавший старое, получает прежний результат.
- Вывод не меняется: по умолчанию остаётся `space`, образцы сравниваются как хранятся.

## Альтернативы

- **Оставить поле в `UnwrapOptions`.** Единственным общим параметром был бы тот, который читает только V2, и каждый
  новый параметр V2 ставил бы тот же вопрос.
- **Удалить старый API сразу.** Библиотека, которой пользуется чужой код, не убирает публичный метод в patch-выпуске.
- **Логический параметр `keepStrayCr=true`.** Сохраняет старое имя, но не стиль параметров V1, и `false` говорит
  меньше, чем `space`.
- **`--keep-stray-cr` в справке как второй способ.** Два способа сказать одно и то же в справке, один из них уходящий.

## Последствия

- `UnwrapOptions` теряет собственное поле; `equals`, `hashCode` и `toString` охватывают только параметры форматов.
- `V2FormatUnwrapper` получает `STRAY_CR_PROPERTY`, `STRAY_CR_OPTION`, `options()` и проверку значения;
  `V2UnitParser` принимает настройку для каждой единицы.
- Командная строка всегда упоминает `--format-option`, потому что у V2 всегда есть параметр.
- Устаревшие члены удаляются в следующем мажорном выпуске вместе с псевдонимом свойства и флагом.
