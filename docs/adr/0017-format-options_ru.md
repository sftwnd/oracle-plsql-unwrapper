# 0017. Параметры отдельного формата

[English version](0017-format-options.md)

## Контекст

`UnwrapOptions` — объект, который доносит параметры до форматов. У формата есть параметры, которых нет у других:
закрытая реализация V1 выбирает раскладку восстановленного текста и параметры, у которых пишется режим `IN`, V2 решает,
что делать со случайным CR текста (ADR 0007, ADR 0018). До сих пор такая настройка задавалась только системным
свойством процесса, о котором справка командной строки не говорит: пользователь узнаёт о ней из документации, а
приложение не может задать её для одного `Unwrapper`.

Требования:

- справка командной строки перечисляет то, что принимают форматы, найденные на class path или module path, и ничего
  больше;
- формат управляется теми же объектами, что и общие параметры, без изменения публичного API на каждый параметр;
- публичный проект не знает параметров закрытого формата и не зависит от него;
- системные свойства продолжают работать.

## Решение

- **Описание.** `FormatUnwrapper.options()` возвращает объекты `FormatOption`: имя, описание в одну строку и допустимые
  значения. Формат без параметров возвращает пустой список (по умолчанию).
- **Значения.** `UnwrapOptions.withFormatOption(format, name, value)` сохраняет значение под `format.name`;
  `formatOption(format, name)` возвращает его или `null`. Объект остаётся неизменяемым. Формат берёт значения в
  `FormatUnwrapper.withOptions` и игнорирует неизвестное ему. Там же он проверяет значения: неверное — это
  `IllegalStateException`, о котором сообщает командная строка.
- **Справка.** `Unwrapper.formatOptions()` перечисляет параметры форматов, у которых они есть. Справка командной строки
  показывает их под форматами, как `V1.layout=source|canonical`, и упоминает `--format-option`, только если параметры
  есть.
- **Командная строка.** `--format-option <формат>.<имя>=<значение>`, повторяется для нескольких параметров; более поздний
  с тем же именем побеждает. После создания unwrapper имена сверяются с `formatOptions()`: параметр, которого не
  перечисляет ни один формат, — неверный аргумент (код возврата 2), потому что формат молча проигнорировал бы его.
- **Свойства.** Параметр сильнее системного свойства той же настройки; чего параметр не задаёт, остаётся за свойством,
  которое читается для каждой единицы, как и прежде.

## Обоснование

- Один общий параметр командной строки не требует изменений, когда у формата появляется новая настройка: её описывает
  формат, справка и проверка следуют за ним.
- Описания приходят от формата, поэтому справка дистрибутива без V1 его не упоминает, а публичный проект свободен от
  имён закрытого.
- Значения строками в `UnwrapOptions` не тянут типы закрытого модуля в SPI; формат преобразует их и отклоняет неверные
  своим сообщением.
- Проверка имён в командной строке ловит опечатку в параметре, которую скрыла бы терпимость форматов.

## Альтернативы

- **Флаг на настройку** (`--v1-layout`). Проще набирать, но командная строка должна была бы знать каждую настройку
  каждого формата, публичного или нет.
- **Типизированные параметры в `UnwrapOptions`.** Переносит типы каждого формата в SPI.
- **Только системные свойства.** Ничего менять не нужно, но справка не может их перечислить, а один процесс не может
  использовать две настройки.

## Последствия

- Формат может добавлять параметры без изменения публичного API; SPI растёт на `FormatOption`,
  `FormatUnwrapper.options()` и два метода `UnwrapOptions`.
- Пользователь находит параметры формата в `--help`, а приложение задаёт их для каждого `Unwrapper`.
- Значение сама командная строка не проверяет: неверное сообщает формат при создании unwrapper, с кодом возврата 1.
